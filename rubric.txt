Repository Quality Rubric for This Autonomous App Loop Scaffold

1. Purpose alignment
- Does the repository clearly optimize for performing `purpose.txt` as well as possible?
- Is the relationship between purpose, plan, execution, evaluation, and promotion explicit?

2. Control-plane clarity
- Is it obvious which files are live project control-plane records versus Canon templates?
- Is the distinction between scaffold root state and `project/` work surface easy to follow?

3. Loop rigor
- Does the scaffold define a concrete planner -> executor -> evaluator -> memory loop?
- Are promotion, discard, and release decisions tied to fresh evidence rather than vague narration?

4. Reusability
- Can a downstream user copy the Canon-owned scaffold package plus `CANON/` and understand how to operate it with minimal explanation?
- Are the required files and operating stages explicit rather than hidden in prose?

5. Honesty of automation claims
- Does the repository avoid pretending a fully automatic runtime engine exists when it does not?
- Are current automation limits and human-in-the-loop expectations stated plainly?

6. Extensibility
- Can domain-specific rubrics, skills, and project types be added without breaking the core loop?
- Does the Canon catalog stay broad and legible as the scaffold grows?

7. Documentation quality
- Are the root docs, scaffold docs, and AGENTS contracts consistent with each other?
- Are the main rules visible in the files where operators will actually look?

Scoring guidance:
- Strong: a user can run a downstream application project with a clear autonomous loop and no hidden assumptions.
- Medium: the loop is promising but some routing, state, or promotion behavior still relies on interpretation.
- Weak: the purpose-first delivery model remains ambiguous or the scaffold overstates what is automated.
